EXECUTION INSTRUCTIONS FOR MATLAB AND VERILOG
================================================

Purpose
-------
This document provides step-by-step instructions for running the MATLAB
reference model and simulating, synthesizing, and implementing the Verilog
motion-estimation design. Replace example filenames and settings with the
actual names and parameters used in your project.

A. MATLAB REFERENCE MODEL
-------------------------

Requirements
1. Install the MATLAB release actually used for the experiments.
2. Gather the MATLAB source scripts and any required functions.
3. Obtain the exact Xiph video sequences specified in the manuscript.
4. Check whether the scripts require additional MATLAB toolboxes.



MATLAB execution steps
1. Download the exact Xiph video sequences identified in the manuscript.
2. Verify each sequence's filename, original resolution, frame rate, pixel
   format, and frame range against the experimental description.
3. Place the video files in the project's data folder.
4. Open MATLAB.
5. Set MATLAB's Current Folder to the directory containing the main script.
6. Open the main script and verify the input file paths, frame range, grayscale
   conversion, block size, search-window size, search-pattern settings, and
   output directory.
7. Ensure that preprocessing matches the manuscript. Do not crop or resize
   frames unless specified in the actual experiment.
8. Run the script using the Run button. Alternatively, type the script name
   without the .m extension in the Command Window. For example, main.m    
9. Check the Command Window for errors and warnings.
10. Check the results directory for outputs actually generated by the scripts,
    such as motion vectors, PSNR values, logs, or figures.
11. Repeat the procedure for each sequence and frame range in the experiment.
12. Record the MATLAB release, input sequences, frame ranges, parameters, and
    output filenames.

Check MATLAB version
1. Enter the following in the MATLAB Command Window:
       version
2. To identify the release, enter:
       version('-release')
3. Record the result. Report the version actually used for the published
   experiments; do not claim a newer version unless the experiments were
   rerun and verified with it.

B. VERILOG SIMULATION IN AMD VIVADO
-----------------------------------

Requirements
1. Install the Vivado Design Suite version actually used for the experiments.
2. Gather all Verilog source files, the testbench, and any memory initialization
   files or IP configuration files required by the project.
3. Identify the correct Virtex-7 FPGA part number used in the implementation.
4. Prepare the clock constraint file.

Clock constraint example
For a 100 MHz clock on input port clka, create a file named
virtex7_clock.xdc containing:

    create_clock -name clka -period 10.000 [get_ports clka]

This is an XDC example for Vivado. Confirm the clock period matches the
experiment. Add any required pin constraints or other timing constraints
used in the actual design.

Create and configure the Vivado project
1. Open AMD Vivado Design Suite.
2. Select Create Project, provide a project name and location, and proceed
   through the wizard.
3. Select RTL Project. Add the Verilog design files.
4. Add the testbench files as simulation sources.
5. Select the exact Virtex-7 FPGA part number used in the paper.
6. Add the XDC constraint file under Constraints.
7. Set the correct top-level design module and simulation top module.
8. If the design uses block memory IP, add the corresponding IP configuration
   and initialization files and confirm their settings.

Run behavioral simulation
1. In the Flow Navigator, select Run Simulation > Run Behavioral Simulation.
2. Allow the simulation to run.
3. Inspect the waveform and testbench messages.
4. Confirm that reset, start, input data, candidate positions, completion
   signals, and output values behave as expected.
5. Save relevant waveforms or logs if they are part of the reproducibility
   package.
6. Compare Verilog outputs against MATLAB results using identical input frames,
   block coordinates, search patterns, and termination conditions.

Run synthesis and implementation
1. In the Flow Navigator, select Run Synthesis.
2. Review the synthesis status and utilization report.
3. Select Run Implementation after synthesis completes.
4. Review placement and routing results.
5. Open the timing summary and record the achieved timing, slack, and clock
   constraints.
6. Record LUT, flip-flop, BRAM, DSP, and other relevant resource utilization
   values from the reports.
7. Save the reports and implementation settings needed to reproduce the results.

Check Vivado version
1. In Vivado, open Help > About to view the installed version.
2. Alternatively, use the version information shown when Vivado starts.
3. Record the exact release used for synthesis, implementation, and timing
   analysis.

C. MATLAB–VERILOG COMPARISON
----------------------------

1. Use the same source video frames and frame indices in both implementations.
2. Apply the same grayscale conversion, cropping, and preprocessing procedure.
3. Match block dimensions, search-window dimensions, search patterns, coordinate
   offsets, strides, candidate ordering, and termination rules.
4. Document numeric differences between MATLAB and Verilog, including integer
   conversion, signedness, bit widths, rounding, overflow, and saturation.
5. Compare corresponding motion vectors and other algorithm outputs.
6. Investigate any mismatches before calculating or reporting PSNR and hardware
   results.
7. Record the test cases and comparison results so another researcher can
   repeat the experiment.

---------------------------------------------------------------------------

The MATLAB reference model was executed using MATLAB R2026b, and the Verilog 
design was simulated, synthesized, and implemented using AMD Vivado Design Suite 2026.1. 
The execution procedure includes MATLAB script execution, Verilog behavioral simulation, 
FPGA synthesis, implementation, and timing analysis. The clock constraints, testbench configuration, 
and comparison procedure between MATLAB and Verilog outputs are documented to facilitate reproducibility.
